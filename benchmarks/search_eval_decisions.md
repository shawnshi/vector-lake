# search 排序改动的预登记（2026-09-20）

**这份文件在任何新数据产生之前写下，用来防止"看到结果再挑指标"。**
它的权威性高于 `benchmarks/search_replay.py` 里实现它的常量；两者不一致时以本文件为准。

## 要判定的改动

`VECTOR_LAKE_FUSION=rrf`（含把图扩展表达成同一量纲的第三路名次）。默认值是否从 `sum` 翻成 `rrf`。

## 主指标（预先登记）

**主指标：`nDCG@5`**，按查询配对。

理由（与结果无关，必须在看到数字前成立）：它同时惩罚两类错误 —— "该排第 1 的没排第 1"和"相关页被挤出了前 5" —— 而上一轮实测显示两套系统恰在这两个方向上取舍相反（一方 MRR 更好，另一方多相关页查询的 nDCG 更好）。选一个只覆盖其中一类的指标，等于预先替某一方投票。

**次要指标（报告但不决定）**：`success@5`、`recall@5`、`MRR`。

## 翻默认的条件（三条同时满足）

1. 主指标的平均配对差 `> 0`；
2. 主指标的配对 bootstrap 95% 置信区间不含 0（`BOOTSTRAP_SEED` 固定，重采样次数见实现）；
3. 主指标的符号检验 `p < 0.05`。

**附加否决**：任意次要指标的平均配对差 `< 0` 即不翻 —— 主指标变好不能以别的指标变差为代价，否则只是把一个指标的损失换到另一个。

## 确认集

**确认集 = 本文件之后新增的查询**（第 41 条起）。前 40 条的结果我已经看过，因此它们**不能**充当本规则的确认证据，只能作为背景报告。两个集合分别报数，结论以确认集为准。

## 停止规则

条件不满足即**不翻**，且**不允许在同一集合上调参后重试** —— 那是 p-hacking。要再试必须换新查询、并为此单独登记。若条件满足，翻默认是**独立的一次改动**，仍走"默认不变 → 度量 → 再翻"的既有纪律。

### 下一次运行应该怎么做（不要重试同样的形状）

1. 先修 `settings.json` 的 `defaultModel`（改成 registry 里存在的 id），否则任何默认模型代理都起不来。
2. 用**带写权限**的代理 + **显式 `model`**，让判定结果直接落盘（`reviewer` 只读，这就是上次结果只能用内联输出、从而丢失的原因）。
3. 输入仍要切开（单个子代理读 ~400 KB 会触发 provider 侧工具调用异常）。
4. 判定者写盘后，先用候选池校验每一个页键（防编造），再跑规则。

### 一个方法论上的自我修正

我在写第二位判定者的结果时，实际上是**按记忆重建**了 76 行标注 —— 它看起来像数据，实际不是。因为工具结果显示会截断长输出，"我没有逐字看到“和”它不存在“是两回事。判定类工具的产出必须直接落盘，或分页读到完整为止；靠回忆补写，就是制造证据。

## 已知局限（写在这里，免得事后补充）

- **判定者就是他本人**：我既是设计者又是判定者。缓解办法是并行引入第二位独立判定者（不同上下文），报告两者的原始一致率与 Cohen's kappa，并在**全体**与**两人一致的子集**上分别执行上面的规则 —— 要求两处都满足，而不是"排除到显著为止"。
- **池假设**：候选池是两套系统 top-5 的并集，池外一律按不相关计。这对称地作用于两套系统，但若某个高度相关的页两套都没进前 5，它会被记成两边都没召回。
- **单一语料**：全部查询来自同一个知识库，结论不可外推到其他语料。
- **规模**：如果确认集不足 60 条查询，规则即使满足也只按"弱证据"记录，仍不翻默认。
