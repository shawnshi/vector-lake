# search 排序改动的预登记（2026-09-20）

**这份文件在任何新数据产生之前写下，用来防止"看到结果再挑指标"。**
它的权威性高于 `benchmarks/search_replay.py` 里实现它的常量；两者不一致时以本文件为准。

## 要判定的改动

`VECTOR_LAKE_FUSION=rrf`（含把图扩展表达成同一量纲的第三路名次）。默认值是否从 `sum` 翻成 `rrf`。

## 主指标（预先登记）

**主指标：`nDCG@5`**，按查询配对。

理由（与结果无关，必须在看到数字前成立）：它同时惩罚两类错误 —— "该排第 1 的没排第 1"和"相关页被挤出了前 5" —— 而上一轮实测显示两套系统恰在这两个方向上取舍相反（一方 MRR 更好，另一方多相关页查询的 nDCG 更好）。选一个只覆盖其中一类的指标，等于预先替某一方投票。

**次要指标（报告但不决定）**：`success@5`、`recall@5`、`MRR`。

## 翻默认的条件（三条同时满足）

1. 主指标的平均配对差 `> 0`；
2. 主指标的配对 bootstrap 95% 置信区间不含 0（`BOOTSTRAP_SEED` 固定，重采样次数见实现）；
3. 主指标的符号检验 `p < 0.05`。

**附加否决**：任意次要指标的平均配对差 `< 0` 即不翻 —— 主指标变好不能以别的指标变差为代价，否则只是把一个指标的损失换到另一个。

## 确认集

**确认集 = 本文件之后新增的查询**（第 41 条起）。前 40 条的结果我已经看过，因此它们**不能**充当本规则的确认证据，只能作为背景报告。两个集合分别报数，结论以确认集为准。

## 停止规则

条件不满足即**不翻**，且**不允许在同一集合上调参后重试** —— 那是 p-hacking。要再试必须换新查询、并为此单独登记。若条件满足，翻默认是**独立的一次改动**，仍走"默认不变 → 度量 → 再翻"的既有纪律。

### 结论：默认保持 `sum`

RRF 在 **16/16 个 指标×标注集** 组合上都方向一致地更好，但按预先登记的规则，它**没有过关**。

**而这次预登记正好拦下了一次挑指标的机会**：如果当初把主指标定成 recall@5，judge-a 下 recall 是 `0.7302 → 0.8535`，CI `[+0.029, +0.219]`、p=0.011 —— **规则会通过**。主指标一旦事后改，结论就会反过来。这正是先把规则写下来、而不是先看数字的意义。

另：上一轮（40 条、单一判定、单标签）显著的是 MRR；这一轮更严格的集上 MRR 反而不显著、recall 显著 —— **哪个指标“赢”本身就不稳定**，所以不能拿“哪个过了”当结论。

### 对判定质量的诚实说明

两位判定者**同模型族（`deepseek/deepseek-v4-pro`，workflow 级覆盖）、不同上下文**，不是两个不同模型。kappa 0.73 说明口径可复制，但共同模型偏置无法由此排除。若要把结论从“未证实”推到“已证实”，需要的不是更多同模型判定，而是：第二位**不同模型族**的判定者 + 把主指标与最小效应量写进登记（例如“nDCG@5 至少 +0.05 且 CI 不含 0”），而不是只看“> 0”。

## 规则修正（2026-09-21，在第三位判定者测量**之前**写下）

**修正点**：主指标除 `> 0` 外，另要求**最小效应量** —— nDCG@5 的平均配对差 **≥ +0.05（绝对）**。其余条件不变。

**为什么必须如实登记这是事后加的**：这个修正写于**看过确认集结果之后**。它只会让通过更难（四个点估计是 `+0.0685 / +0.0232 / +0.0472 / +0.0446`，其中两个低于 0.05），所以不构成“调参到显著”；但它确实改变了规则，因此只约束**它之后**的测量，**不追认本轮已出的 NOT MET**。

**第三位判定者的定位（先定性质，再看结果）**：它不是新的确认集 —— 查询还是同样的 76 条。它是一次**稳健性复现**：换一个**不同模型族**、独立上下文的判定者，看结论是否随判定者变化。一个不同模型族的判定者可以暴露共同模型偏置，但换不了查询，所以它强度低于“新查询确认”。

**判定动作（先写，后看）**：
- 需**同时**满足：在**第三位判定者**的标注下规则通过，**且**在**两人交集**（judge-a ∩ judge-b，最严）的标注下规则通过。两处都过 → 翻默认是**独立一次改动**；任一处不过 → 默认继续是 `sum`。
- **不允许在三个标注集里挑一个通过的** —— 上一条的“两处同时”就是为了封死这个口子。
- 若第三位判定者连启动都失败（上一轮踩过），停止并报告车道状态，**不换协议重试**。

## 已知局限（写在这里，免得事后补充）

- **判定者就是他本人**：我既是设计者又是判定者。缓解办法是并行引入第二位独立判定者（不同上下文），报告两者的原始一致率与 Cohen's kappa，并在**全体**与**两人一致的子集**上分别执行上面的规则 —— 要求两处都满足，而不是"排除到显著为止"。
- **池假设**：候选池是两套系统 top-5 的并集，池外一律按不相关计。这对称地作用于两套系统，但若某个高度相关的页两套都没进前 5，它会被记成两边都没召回。
- **单一语料**：全部查询来自同一个知识库，结论不可外推到其他语料。
- **规模**：如果确认集不足 60 条查询，规则即使满足也只按"弱证据"记录，仍不翻默认。
