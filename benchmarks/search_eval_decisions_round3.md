## 1. 第二批暴露的两个缺陷（事实）

| 缺陷 | 实测 |
|---|---|
| 判据可能不可满足 | 333 条查询里 **80%** 在主判定者眼里"池内没有任何主体对得上的页"；深度提到 top-20 后仍有 **213/268（79.5%）** 一条都找不到 |
| 分母名不副实 | `minimum_sample` 的分母是 `judged`，于是 **333 条全数通过**，而其中只有 **65 条**是"有页可找"的（confirmable） |

规则卡已记录这两点，并指出 **+0.05 这个绝对门槛在不同查询构成下不可比**（第一批 0.18 SD、第二批 0.41 SD）。

---

## 2. 判据：采用放宽（已确认 2026-09-22）

| 臂 | 判据文字 |
|---|---|
| 严格（第一、二批） | `相关 = 该页的主体内容就是查询所指的东西，或是对它的专门论述` |
| **放宽（第三批）** | `相关 = 这页能实质性回答查询所问 —— 覆盖查询的某个要点，或给出可直接采用的事实、方法、机制。只是同领域泛泛相邻、答不上问题的，不算相关` |

**理由**：语料的页是单主体的，查询是组合式的（`<实体> 的 <方面>`）。在"主体恰好等于查询所指"这条尺子下，这类查询常常**没有任何页面能合格**，于是主指标退化成"有多少查询是无解的"，而不是"排序把可找的页排得好不好"。

**支撑测量（判据 A/B）**：把 34 条"严格判据下 top-20 内也无相关页"的查询，用**完全相同的候选池**、同一位判定者、只改判据文字重判一次（12 批，顺序执行）。
→ 结果在本节末尾补入，**期间不预支结论**：严格与放宽的差别若很小，说明卡点不在判据；若很大，则证实判据是主要约束。

**判据效应（A/B 已全部落盘，12/12 批，2026-09-22）**：

| | |
|---|---|
| 样本 | 44 条查询（严格与放宽两次判定，候选池逐字相同）|
| 严格判为**零相关**的 | 34 条 |
| 其中放宽后**出现相关页** | **17 条 = 50%** |
| 放宽后新增的页次 | 35 |
| 反向检查 | 严格判为**有**相关的 10 条，放宽后**全部仍为有**（10/10）—— 放宽是单调的，不会删掉已有的相关 |

**结论**：严格判据说“池里没有任何页主体对得上”的查询，**一半其实有页能实质性回答它**。判据确实是主要约束之一（与 P0 的“79.5% 在 top-20 内也没有”合并看：一部分是无解，一部分是尺子太严）。这也反向支持了采用放宽判据的决定。

## 3. 分母与门槛（已确认，已实现）

| 项 | 值 | 来源/理由 |
|---|---|---|
| `comparison_universe.denominator` | **`confirmable`** | 均差解释为"把可找的页排得好不好"；confirmable 由**两条融合的并集**是否命中定义，因此与具体臂无关 |
| `minimum_sample` | **≥ 100 confirmable**（原 300 judged） | 第二批只有 65 条 confirmable，这是"300 条查询"被读成 300 条证据的根源 |
| `query_construction.min_confirmable_queries` | **100** | 与上一行同值、故意重复：样本门拒的是"宇宙太小"，这条拒的是"查询里没得可找"，且在未来把分母改回 `judged` 时仍然有效 |
| 主指标门槛 | **Δ ≥ 0.30 SD**（配对差的标准差），绝对量 +0.05 降为**报告项** | 绝对门槛跨构成不可比（0.18 vs 0.41 SD）；SD 单位把门槛与构成解耦 |
| bootstrap 95% CI 不含 0 | 不变（唯一显著性门） | |
| 符号检验 | 报告项 | 第二批已降级 |
| 次要指标不回退 | 不变 | |

**功效依据**：d=0.30、n=100 时双侧 α=0.05 约 **85%** 功效；n=65（第二批实况）约 65%。

**实现的副作用（必须知道）**：分母为 `confirmable` 时，比较**要求每个 run 记录可验证的标签版本**（`labels` 路径 + `labels_sha256`）。缺记录或哈希不再吻合 → `--compare` **直接拒绝**（fail closed），而不是回退到 `judged` 静默读数。早期产出的 run 文件没有这两个字段，需要重跑才能参与 1.2 下的比较。

**同时报告的义务**：第三批必须**并列报告 `judged` 全量上的均差**。`confirmable` 作分母会让"提高召回"同时改善分子与分母，长期对排序改动更有利 —— 两者之差本身就是"无解查询占比"的读数，不并列就不算读完整。

## 4. 第三批执行纪律（写死）

| 项 | 规定 | 依据 |
|---|---|---|
| 语料 | 标签与计分必须同源；池文件与 run 都写 `corpus` 指纹，不一致直接拒绝 | 第二批池与计分跨了向量兜底补齐，330/333 查询不一致 |
| 标签版本 | run 记录 `labels_sha256`；两臂必须同版本，验证不了就拒绝比较 | 规则卡 1.1 / 1.2 |
| 判定者 | 主判定者预先指定；**同一 provider 的 child 不得并发**（凭据存储是带锁文件，争用表现为静默卡死到超时） | P1b 三轮实测 |
| 批粒度 | 每 child ≤20 查询；写进登记并**保持恒定** | 包装效应 90.0% vs 时点 86.7%（n=30） |
| 编排 | 顺序编排逐 child 隔离失败；文件名差异放在**首部**，不要只差末位字符 | 一次失败取消后续；`b09a` 写成 `b09b` 丢掉一半 |
| 判定者信度 | 至少对一个子集重复判定，结论附重测一致率 | P1b：88.2% 完全一致、Jaccard 0.894；衰减全额修正后第二批结论不变 |

# 第三批结果（2026-09-22）

## 仪器（与前两批的差别，逐条可核）

| 项 | 值 |
|---|---|

| 判据 | **放宽**（per §2） |

| 判定者 | 主 `antigravity/gemini-3.8-flash`、`deepseek/deepseek-v4-pro`、`openai-codex/gpt-5.6-luna`，各 300/300，零格式问题 |

## 标签

| 判定者 | 相关页次 | 零相关 | **confirmable** | 每查询相关页 |
|---|---|---|---|---|
| p（主） | 483 | 34 | **266** | 1.61 |
| d1 | 945 | 3 | 297 | 3.15 |
| d2b | 1128 | 4 | 296 | 3.76 |
| **共识**（三方交集） | 471 | 36 | **264** | 1.57 |

**两两 Cohen's kappa（查询×候选）**：p↔d1 **0.520**、p↔d2b **0.401**、d1↔d2b **0.699**。
对照第二批（严格判据）：0.352 / 0.396 / 0.678 → **放宽后 p↔d1 明显收敛**（0.352→0.520），另两对基本不动。

**放宽判据的两个可测后果**（必须与结论一起读）：confirmable 从第二批的 65 → **266**（越过 ≥100 门）；但每查询相关页从 0.27/1.20/0.92 → **1.61/3.15/3.76**，nDCG@5 的绝对水平因此从 ≈0.12 抬到 **0.85–0.88**，两臂的差异被压缩。

## 规则判定（规则卡 1.2）

| 门 | 主判定者 | 严共识集 |
|---|---|---|
| SD 单位效应量 ≥ **0.30 SD** | **FAIL（+0.0219 = 0.101 SD）** | **FAIL（+0.0211 = 0.101 SD）** |
| bootstrap 95% CI 不含 0 | **FAIL [−0.004, +0.048]** | **FAIL [−0.004, +0.046]** |
| 次要指标不回退 | **FAIL（recall −0.0174）** | **FAIL（success −0.0038、recall −0.0161）** |

| 绝对量 +0.05（报告项） | +0.0219（0.230 SD） | +0.0211（0.240 SD） |

**两处都 NOT MET。**

**同时稳定出现的另一面（报告项）**：`rrf` 的 **MRR 显著更好** —— 主判定者 +0.0511（CI [+0.024,+0.079]、符号检验 p=0.0027）、共识 +0.0466（CI [+0.020,+0.074]、p=0.0055）。即 RRF 的一贯取舍：**把找到的排得更好，同时找到的更少**（recall 回退）。

## 判定动作（§5）

- **默认继续 `sum`**，RRF 保持 opt-in；
- 记录 **"RRF 未被证实"**（第三批、第三把尺子、两次不同判据，全部 NOT MET）；
- **停止**对这个改动的评估；**没有**改换主指标（例如改用 MRR —— 那会让结论翻转，正是预注册要防的事）、**没有**改换判定者或标注集重算。

## 三批并列（同一变更，三种仪器）

| 批次 | 判据 | 主指标 Δ | CI 是否不含 0 | 结论 |
|---|---|---|---|---|
| 第一批（116 查询，76 确认集） | 严格 | +0.0348 / +0.0472 / +0.0462 / +0.0442（四标注集） | 否 | NOT MET |
| 第二批（333 查询，65 confirmable） | 严格 | +0.0132 / +0.0121 | 是 | NOT MET（栽在 +0.05 绝对门槛） |

三次都是**同一方向、同一量级、都够不到门槛**；而 RRF 的 MRR 优势在三批里都稳定为正。要让它变成"可采纳"，需要的是**补上 recall 的缺口**（那是它自己的取舍），而不是把主指标换成 MRR。

# 追加：实体名优先（`VECTOR_LAKE_ENTITY_NAME_PRIORITY`）——2026-09-23

**问题**：九个问法（三个主体）显示同一现象——裸实体名让主体页排第 1（1.000），加上分析式框架词
（"核心价值、优势及市场竞争力"）后掉到第 2/5/6/13 名，因为那些词出现在**分析该实体的文档**里，
不在实体自己的页面上。机制是查询被当成词袋，实体身份没有独立信号。

**仪器**：r3 标注集（`search_eval_labels_r3_p.jsonl`、`_r3_consensus.jsonl`，300 条）、
`--vectors snapshot`（冻结向量）、`benchmarks/search_replay.py --compare` 的配对统计与
`benchmarks/search_eval_rule.json` 的预注册判定规则。开关已写入回放 config——否则 `--compare`
会以"同一配置"拒绝该对比，两次不同排序行为的运行也会在记录里无从区分。

**结果（left=0 默认，right=1）**

| metric | left | right | diff | 配对统计 |
|---|---|---|---|---|
| success | 0.9774 | 0.9812 | **+0.0038** | CI [−0.007, +0.019] p=0.785 |
| recall | 0.9276 | 0.9206 | **−0.0070** | CI [−0.023, +0.010] p=0.399 |
| reciprocal_rank | 0.8630 | 0.9181 | **+0.0551** | CI [+0.025, +0.087] p=0.000 |
| ndcg（primary） | 0.8472 | 0.8747 | **+0.0275** | CI [+0.005, +0.051] p=0.015 |

**判定**：`RULE NOT MET: keep the default`
- primary CI 不含 0 ✓ 通过（266 条 confirmable）
- **最小效应量不达标**：+0.143 SD vs 注册门槛 +0.30 SD
- **次级门失败**：recall 回退 −0.0070
- sign test p=0.7596（46 胜 / 50 负）

**保留的机制诊断**：回退来自"查询点名了一个实体，但标签要的是另一张页"的情形——
`梅奥诊所人工智能实践` 1.000→0.500、`健康中国 的核心机制` 1.000→0.500、`shawnshi` 1.000→0.500
（点名了人物页，标签要的是技能产品页）。这是分层把"点名"当作等价于"要它"的代价。

**动作**：默认保持 `0`，开关保留供后续预注册问题使用；`tests/test_entity_name_tier.py` 钉住机制
（含"默认排序不得被改动"）。
