## 2024-05-19 - [DOM XSS Mitigation via innerHTML Sanitization]
**Vulnerability:** In `templates/topology.html`, user-provided data from Markdown files (e.g., node names, labels, states, and groups) was interpolated directly into `innerHTML` strings without being escaped. It also embedded dynamic node IDs directly into `onclick="selectNode('${id}')"` attributes. This exposes the frontend to DOM-based XSS if a node property contains an injected HTML payload (e.g., `<script>alert(1)</script>`).
**Learning:** Jinja variables rendered as JavaScript literals (`const rawData = %%GRAPH_DATA%%;`) bypass backend template escaping. Even in a static client-side application using `file:///`, if untrusted data from local parsed files is assigned directly to `innerHTML`, DOM XSS is possible. Furthermore, injecting properties directly into HTML strings for event handlers (e.g. `onclick`) leads to code execution or parsing syntax errors when variables contain quotes or single quotes.
**Prevention:** Always implement a strict client-side `escapeHTML` function when working with string templating and `innerHTML`. When building interactive DOM elements with dynamic references, avoid interpolating values into inline JS (`onclick`); instead, safely assign text via `textContent` (or `innerText`) and attach variables to `data-*` attributes (e.g., `this.getAttribute('data-id')`), letting standard `addEventListener` or functional `onclick` callbacks handle them safely.
