## 2024-05-30 - Server-Side XSS via JSON Serialization in HTML Templates
**Vulnerability:** A Server-Side XSS vulnerability was identified in `vector_lake/tool_graph.py`. A Python dictionary was serialized to a JSON string and injected directly into an HTML template inside a `<script>` tag using basic string replacement (`html.replace("%%GRAPH_DATA%%", json.dumps(...))`). This allows malicious input (like `</script><script>alert(1)</script>`) to break out of the script context and execute arbitrary JavaScript.
**Learning:** This existed because `json.dumps()` guarantees syntactically valid JSON, but it does not inherently escape characters that have special meaning in HTML (`<`, `>`, `&`). When JSON is embedded directly in HTML, the browser's HTML parser runs *before* the JavaScript parser. If the JSON contains `</script>`, the HTML parser interprets it as the end of the script block, regardless of JSON string boundaries.
**Prevention:** When injecting JSON directly into HTML `<script>` tags from Python, always escape HTML-sensitive characters (`<`, `>`, `&`) to their Unicode equivalents (`\u003c`, `\u003e`, `\u0026`). In Python, this can be done securely by chaining `.replace('<', r'\u003c')` after `json.dumps()`. Alternatively, load the data asynchronously via an API, or pass it via a safely encoded `data-*` attribute on an HTML element and parse it with `JSON.parse()`.
