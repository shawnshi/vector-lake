## 2024-05-24 - Cross-Site Scripting (XSS) in Graph Topology UI
**Vulnerability:** Both Server-Side XSS and DOM-based XSS were discovered in the application's graph topology components. First, `vector_lake/tool_graph.py` serialized a raw dictionary into a JSON string and injected it directly into an inline `<script>` block (`%%GRAPH_DATA%%`), allowing malicious node names (e.g., `</script><script>alert(1)</script>`) to execute arbitrary code. Second, `templates/topology.html` used `.innerHTML` extensively to construct the DOM using values extracted from the JSON graph data without properly escaping HTML characters, allowing payloads containing HTML tags (like `<img src=x onerror=alert(2)>`) to render and execute.
**Learning:** Hardcoded static UI templates that embed data directly into their `<script>` tags must strictly serialize and escape JSON to avoid injection. Using `.innerHTML` when creating UI elements dynamically in JavaScript exposes the app to XSS if the data source contains unsanitized user content.
**Prevention:**
1. Server-Side: When injecting JSON into HTML `<script>` tags via Python, escape problematic HTML characters after serialization by using `.replace('<', r'\u003c').replace('>', r'\u003e').replace('&', r'\u0026')`. This prevents breaking the script block boundaries.
2. DOM: Never trust node attributes like `name` or `group` in a template. Use a robust `escapeHTML` function before inserting any variable into `.innerHTML` string interpolation, or prefer safe alternatives like `.textContent` and `.innerText`. Also, always use `encodeURI()` for dynamic `href` properties.
