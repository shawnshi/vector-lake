## 2024-05-15 - [Preventing DOM XSS via innerHTML]
**Vulnerability:** Found multiple instances of unescaped variables being interpolated directly into `innerHTML` strings within `templates/topology.html`. Examples include injecting `node.name`, `node.id`, `targetId`, and `source`. Since these values can originate from markdown files and might contain user-controlled data or untrusted content, this creates a high-risk DOM-based Cross-Site Scripting (XSS) vulnerability.
**Learning:** Using template literals to build HTML strings and assigning them directly to `innerHTML` is a dangerous pattern in modern JavaScript when handling untrusted data. The data needs to be properly escaped or, ideally, constructed using safe DOM APIs like `document.createElement()` and `textContent` or `innerText`.
**Prevention:** Always use safe DOM manipulation methods (`textContent`, `innerText`, `setAttribute`) or a dedicated HTML escaping function before injecting dynamic data into the DOM. Never trust input data, even if it comes from an internal system like a wiki or graph database, as the source markdown could be modified by users.
